# GeoCore website

Static site published by Netlify from this folder (`netlify.toml` at the repo root sets `publish = "website"`).
There is no framework runtime: a small Python generator renders Jinja2 templates into plain HTML, and the
generated HTML is committed. Netlify does not run the build.

## Build

From the repository root:

```bash
python-backend/venv/Scripts/python.exe website/_build/build.py    # Windows
python-backend/venv/bin/python website/_build/build.py            # macOS/Linux
```

Needs `jinja2`, `markdown` and `pyyaml` (CI installs just these; `markdown` is not in `python-backend/requirements.txt`, so `pip install markdown` if it is missing). CI rebuilds the site and fails if the marketing pages (`index`, `about`, `download`, `privacy`, `404`) differ from what is committed, so commit the regenerated HTML. Re-run the build after editing
anything in `_templates/`, `_data/` or `assets/` (asset URLs carry a content hash, `?v=…`, for caching).

Preview locally:

```bash
cd website && python -m http.server 8765    # then open http://localhost:8765/
```

### Facts pulled from the code base at build time

| Shown on the site | Source |
| --- | --- |
| Calculation counts per Groundhog domain, total (220) | `python-backend/core/function_manifest.json` |
| GeoAI model list and sizes | `RECOMMENDED_MODELS` in `python-backend/core/geoai/model_downloader.py` (parsed with `ast`, not imported) |
| App version on the privacy page | `electron-app/package.json` |

Each has a fallback snapshot in `build.py`, and the build prints a warning if it is used. The descriptive
copy for each domain is in `DOMAINS` in `build.py`; the build warns if the manifest contains a Groundhog
package with no copy.

## Layout

```
_build/build.py          generator: marketing pages + docs (render(), render_docs_page(), write_search_index())
_build/docs_content.py   docs pipeline: _content Markdown -> HTML (math stash, links, attribution data, search entries)
_build/app_docs.py       desktop app Guide & Theory: api.json -> electron-app/src/features/calculations/guide/functionDocs.json
_content/                docs source, generated by _content/extract_docs.py (input only; see _content/README.md)
_templates/
  base.html              shared chrome: header, mobile nav, footer, theme toggle
  index.html about.html privacy.html download.html 404.html
  docs_base.html         three-column docs layout (extends base.html via the `layout` block)
  docs_page.html         generic docs page (renders page.body_html)
  docs/index.html        docs landing (section cards from the nav)
assets/css/site.css      the design system (tokens, components, page styles, docs content, code highlighting)
assets/icons.svg         SVG icon sprite (<use href="assets/icons.svg#i-NAME">)
assets/js/               theme-init.js (head), site.js, download.js, docs.js, math.js
assets/vendor/katex/     KaTeX 0.18.9, vendored (MIT, LICENSE + VERSION.txt); loaded only on pages with math
docs/                    GENERATED: docs/<slug>/index.html, docs/search-index.json, docs/assets/groundhog/**
```

The build deletes and regenerates everything in `docs/` except `docs/assets/`, which is mirrored from
`_content/groundhog/assets/` (unchanged files are skipped, stale ones removed).

## Templates

`base.html` blocks: `title`, `description`, `head` (extra `<head>` tags), `body_class`, `layout`
(wraps `<main>`; default renders `<main id="main">{% block content %}</main>`), `content`, `scripts`.

Every template receives: `root` (relative prefix to the site root, `''` or `'../'`; `'/'` for 404.html),
`url(path)` (site-root-relative path → link from the current page; `http…` and `#…` pass through),
`asset(path)` (same, plus `?v=<hash>`), `icon(name, cls='icon', label=None)` (inline `<svg><use>`),
`nav_active` (`home|docs|download|about|''`), `repo_url`, `releases_url`, `app_version`, `fn_total`,
`domains`, `models`, `groundhog_version`, `year`, `docs_nav`.

Filter: `mb` formats a size in MB (`986|mb` → `986 MB`, `4400|mb` → `4.3 GB`).

Rules: no inline `<script>` or `style=""` attributes (the CSP is `script-src 'self'; style-src 'self'`),
no third-party requests except `https://api.github.com` from the download page.

## Video tutorials

`tutorials.html` (list) and `tutorial/<id>/` (one page per video, with a custom player) are generated by `build.py` from `electron-app/src/config/tutorials.json`, the same file the app's Help dialog reads. Per tutorial: `youtubeId` (id or any YouTube URL; the build extracts the id), `duration`, `steps`, and `chapters` as `[seconds, title]` pairs. The poster is `assets/images/tutorials/<id>.jpg` (local, so nothing is requested from YouTube before play).

The player (`assets/js/player.js`, `assets/css/player.css`) draws its own controls over the YouTube IFrame API: chapters, speed, volume, fullscreen, keyboard shortcuts and `#t=83` deep links. The YouTube script and frame load only after the visitor presses play, from `www.youtube.com` and `youtube-nocookie.com`; both are allowed by name in the CSP in `netlify.toml`. Keep styles out of inline `style=` attributes (the CSP forbids them); set CSS custom properties from script instead.

## Docs pipeline

### URLs

A content page `_content/pages/<slug>.md` is written to `docs/<slug>/index.html` and served at
`/docs/<slug>/` (`index` → `/docs/`). Netlify serves directories for both `/docs/<slug>` and `/docs/<slug>/`,
and docs pages use **root-absolute** links (`/docs/...`, `/assets/...`) so either form works. Links in the
content written as `/docs/<slug>#anchor` are rewritten to `/docs/<slug>/#anchor` and checked at build time
(unknown slugs and missing images are reported as "content problems").

### Markdown

Python-Markdown 3.10 with `tables`, `fenced_code`, `codehilite` (Pygments, class-based; token colours are
CSS variables in `site.css`, light and dark), `toc` (heading ids, right-hand TOC for h2–h3, h2 only when a page
has more than 40 headings), `attr_list`, `md_in_html`, `sane_lists`. Explicit `<a id="…"></a>` anchors before
headings (API pages) are used as the TOC targets. Tables are wrapped in `.table-wrap` (horizontal scroll, sticky
first column); third-party images (badges) are replaced by their alt text so pages make no external requests.

### Math

`$…$` and `$$…$$` are stashed before Markdown (outside fenced code and code spans) and restored as
`\(…\)` / `\[…\]`, so underscores and asterisks in LaTeX are never touched. Display math containing `&` or
`\\` without an environment is wrapped in `aligned` (what Sphinx does for `.. math::`). Pages with math load
`assets/vendor/katex/*` and `assets/js/math.js`, which renders with auto-render using only the `\(` and `\[`
delimiters. KaTeX sets a few styles via `setAttribute('style')`, which `style-src 'self'` blocks; `math.js`
routes those to `element.style.cssText` (CSSOM, allowed) only while rendering.

### Attribution

Every page gets an attribution block from its front-matter: groundhog pages show author, licence
(`GPL-3.0-or-later`), the upstream source pinned to the shipped groundhog commit (`source_ref` in `api.json`), upstream docs link(s), notebook path and the
"Edited by GeoCore" note; GeoCore pages show author, licence and the files they were written from. API pages
show the module and an "Available in GeoCore" badge when `geocore_available` is true. The build warns if a
groundhog page's `source_url` is not pinned to the tag.

## Docs data contract

### 1. Navigation tree

Built from `_content/nav.json` by `docs_content.load_nav()`: each node becomes
`{title, slug (dashes), content_slug, url: "docs/<slug>/", children}`; `build.normalize_nav()` then adds the
optional keys below (`icon` is set for top-level sections from `SECTION_ICONS` in `build.py`).

```json
{"title": "…", "url": "docs/<slug>/", "children": [], "status": null, "external": false,
 "slug": "…", "icon": null, "summary": null, "key": null}
```

* Top-level nodes are sidebar headings and landing cards; deeper nodes with children render as collapsible
  `<details>`, open along the current page's trail (`page.trail_urls`).
* Reading order (prev/next) and breadcrumbs are computed depth-first from nodes whose `url` starts with `docs/`.

### 2. Page context — `page`

Render a page with `build.render_docs_page(env, page, docs_nav, base_context)` (template `docs_page.html`
by default). `page` is a dict:

| Key | Type | Required | Notes |
| --- | --- | --- | --- |
| `title` | str | yes | `<title>` text (“… — GeoCore Docs”); `title_html` (optional) is used for the `<h1>` |
| `url` | str | yes | Identity and URL, site-root-relative: `docs/<slug>/` (written to `docs/<slug>/index.html`) |
| `description` | str | no | meta description |
| `body_html` | str | no | Rendered, trusted HTML for the article (inserted with `|safe`; sanitise upstream). Headings that appear in `toc` must carry matching `id`s |
| `toc` | list | no | `[{"id": "bearing-capacity", "title": "Bearing capacity", "level": 2}]`, level 2 or 3; empty → two-column layout |
| `breadcrumbs` | list | no | `[{"title": "Docs", "url": "docs/"}, {"title": "Calculation reference", "url": null}]`; ancestors only — the template appends the current page title. Computed from the nav if omitted; `[]` hides the trail |
| `prev`, `next` | dict/None | no | `{"title", "url"}`; computed from the nav order if omitted |
| `source` | dict/None | no | Attribution line, e.g. `{"label": "Groundhog documentation", "url": "https://groundhog.readthedocs.io/…"}` |
| `updated` | str/None | no | ISO date |
| `has_math` | bool | no | Load KaTeX on this page |
| `meta` | dict/None | no | Attribution data from front-matter: `section, origin, author, license, attribution, source_url, groundhog_version, edited_by_geocore, edit_note, upstream_docs_urls[], module, geocore_available, geocore_functions[], notebook, sources[]` |
| `trail_urls` | list | no | Nav ancestors (computed) |

To customise a page type, create a template that `{% extends "docs_base.html" %}` and overrides
`{% block docs_content %}` (see `_templates/docs/index.html`).

### 3. Search index — `docs/search-index.json`

Written by `build.write_search_index(entries)`; loaded lazily by `assets/js/docs.js` the first time the
search box is used (press `/` to focus it).

```json
{
  "version": 1,
  "generated": "2026-09-26",
  "docs": [
    {
      "id": "calc-shallowfoundations-capacity",       // unique
      "title": "Shallow foundation capacity",          // weighted highest
      "url": "docs/calculations/shallow-foundations.html#capacity",  // site-root-relative (or absolute http URL)
      "section": "Calculation reference",             // shown under the title
      "summary": "One-line description.",             // shown under the title, weighted
      "headings": ["Drained capacity", "Undrained capacity"],  // weighted
      "body": "Plain text, keep to a few hundred words per entry"  // lowest weight
    }
  ]
}
```

Matching is case-insensitive substring; every query term must match somewhere; the top 8 results are shown.
The index holds the marketing pages and Groundhog domains (`seed_search_entries()`), one entry per docs page
(body trimmed to 600 characters, up to 30 headings) and one entry per API heading (function/class/method name,
linking to its anchor) from `docs_content.search_entries()`. It is written compact (~255 KB, ~560 entries;
Netlify compresses it) and only fetched when the search box is first focused. `_content/search-index.json`
(the extractor's own format) is not used.
