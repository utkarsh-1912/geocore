Privacy

GeoCore has no accounts, no analytics and no telemetry. Your projects and calculations stay on your computer. This page lists every network request the desktop app can make, and what it stores locally.

Last updated 27 September 2026 · applies to GeoCore {{ app_version }} and this website

Summary

  • Calculations, plots, reports and GeoAI inference run locally. Project data is never uploaded.
  • The app contacts the internet for: update checks (GitHub), interface fonts (Google Fonts), and — only when you ask — AI model downloads (Hugging Face), two optional geological-profile lookups in Groundhog, and map tiles (OpenStreetMap) if you turn on the location map in two Groundhog profile plots. Map tile requests reveal the approximate location of your site.
  • Everything the app stores is in ordinary files on your computer that you can inspect or delete.

This page was written by reading GeoCore’s source code. File references point to the repository at the time of writing so you can check them yourself.

Network activity of the desktop app

Any request to a server reveals your IP address and a user-agent string to that server; this is noted once here rather than repeated below. GeoCore does not add identifiers, usage data or project content to any request.

1. Update check — GitHub

When
About 15 seconds after an installed (packaged) build starts. Development builds never check.
Where
github.com and GitHub’s release-download hosts, for the utkarsh-1912/geocore repository.
What is sent
Standard requests for the latest release metadata (latest.yml / latest-mac.yml). If a newer version exists it is downloaded in the background and installed when you quit. On macOS, current builds are not code-signed with a Developer ID, so the update cannot install there.
Source
electron-app/electron/main.cjs:161–181 (scheduleUpdateCheck, using electron-updater); publish target in electron-app/package.json (build.publish).
To avoid it
Run offline or block the app in your firewall. Failures are ignored and the app keeps working.

2. Interface fonts — Google Fonts

When
Each time the app window loads, if the computer is online.
Where
fonts.googleapis.com and fonts.gstatic.com.
What is sent
Requests for the Arima, Charm, Quicksand, Signika and Ubuntu font files. Google receives the standard request information described above.
Source
electron-app/index.html:9–13.
To avoid it
Offline, the app falls back to system fonts and works normally. Blocking these two hosts in a firewall has the same effect.

3. GeoAI model downloads — Hugging Face

When
Only when you choose to download a model in GeoAI. Nothing is downloaded automatically.
Where
huggingface.co and its file-delivery CDN. The files come from these public repositories: {% for m in models %}{{ m.repo_id }}{{ ', ' if not loop.last else '.' }}{% endfor %}
What is sent
A request for the chosen model file, made by the huggingface_hub library (which identifies itself and its version in the user-agent). No prompts, questions or project data are sent — GeoAI inference happens entirely on your computer.
Source
python-backend/core/geoai/model_downloader.py:152 (hf_hub_download); the model list is RECOMMENDED_MODELS in the same file.
To avoid it
Copy a .gguf file into the models folder yourself (see below), or select a local file path in GeoAI.

4. Optional geological profile lookups — Flanders (DOV) and the Netherlands (GeoTOP)

When
Only if you run one of two Groundhog functions that are part of the calculation list: retrieve_geological_profile_dov or retrieve_geological_profile_bro.
Where
services.dov.vlaanderen.be (Databank Ondergrond Vlaanderen) and www.dinodata.nl (GeoTOP model via OPeNDAP).
What is sent
The coordinates you enter, to fetch the geological model at that location.
Source
Groundhog {{ groundhog_version }}: groundhog/general/soilprofile.py:1396 (DOV) and :1816–1823 (GeoTOP). The GeoTOP lookup also needs the optional netCDF4 package, which is not in GeoCore’s requirements, so it is not expected to work in standard builds.

5. Location map in profile plots — OpenStreetMap tiles

When
Only when one of two Groundhog longitudinal-profile plots is drawn with its location map turned on: plot_longitudinal_profile (CPTs) or plot_fence_diagram (soil profiles), with plotmap set to true. plotmap is off by default. Having X/Y coordinates on the CPTs or soil profiles does not draw a map by itself, and plot_combined_longitudinal_profile ignores plotmap. In GeoCore {{ app_version }}, input validation rejects the CPT and soil-profile lists these plots need before Groundhog runs, and GeoAI has no tool for them. You should not see this request in practice yet. It is listed because the option is already in the app and will take effect once those inputs work.
Where
a.tile.openstreetmap.org and b.tile.openstreetmap.org, OpenStreetMap’s public tile servers. The app window contacts them directly. No Mapbox account or token is involved. When we tested these plots in the app’s own charting library, no other map hosts were contacted: no Mapbox, map-font or icon (unpkg.com) requests.
What is sent
Requests for 256-pixel map images (tiles). Each tile address contains a zoom level and x/y tile coordinates (/{z}/{x}/{y}.png) that identify a fixed square of the Earth’s surface. The tile server can therefore infer the approximate location of your site. The map is centred on the average of the plotted locations at a fixed zoom (Groundhog ignores the mapbox_zoom input). In a test with three CPTs near Ghent, the first view loaded four tiles at zoom level 11, covering about 25 × 25 km around the site. Panning or zooming the map loads more tiles, and zooming in narrows the area they reveal. Your coordinates, CPT or profile names and test data are not sent; the markers and hover labels are drawn on your computer. The map treats X as longitude and Y as latitude, so the tiles match the real site when your coordinates are in degrees (WGS84).
Source
Groundhog {{ groundhog_version }}: groundhog/siteinvestigation/insitutests/pcpt_processing.py:2707–2709 and :2801–2805; groundhog/general/soilprofile.py:1214–1216 and :1256–1260 (mapbox_style='open-street-map'). The tile addresses come from the open-street-map style built into plotly.js (src/plots/mapbox/constants.js), which the app window uses to draw charts. The inputs are defined in electron-app/src/features/calculations/schemas/siteinvestigation.js (plotmap, mapbox_zoom).
To avoid it
Leave plotmap off, which is the default. If you are offline or block these two hosts, nothing is sent, but the map panel has no background and the chart may report a map error.

Local-only traffic

The interface talks to GeoCore’s own engine over http://127.0.0.1:8000. The engine binds to the loopback address only (python-backend/main.py:103), so it is not reachable from other machines and this traffic never leaves your computer.

What GeoCore does not do

  • No analytics, telemetry, crash reporting or advertising SDKs.
  • No accounts or sign-in.
  • No cloud AI: GeoAI never sends prompts or data to a remote model.
  • No web search. GeoAI’s research index is a local SQLite file built from documents on your computer.

Links you click (for example to documentation or GitHub) open in your web browser and are covered by that site’s own policy.

To remove all GeoCore data, uninstall the app and delete the folders listed above. GeoCore does not store data anywhere else.

This website

  • Hosting. The site is hosted on Netlify, which processes standard server logs (IP address, requested URL, user-agent, time) to deliver and protect the site, as described in Netlify’s privacy policy.
  • No tracking. No cookies, analytics, advertising or third-party fonts or scripts. Fonts are your system’s own; icons and styles are served from this site.
  • Download page. Your browser requests api.github.com directly to show the latest release, and files download from GitHub. GitHub receives the standard request information under its privacy statement. The response is kept in your browser’s session storage for 10 minutes to avoid repeat requests.
  • Tutorial videos. Tutorial pages show a poster image served from this site. Only when you press play (or pick a chapter) does your browser load the video from YouTube (youtube-nocookie.com), under Google’s privacy policy. The “Watch on YouTube” links work the same way.
  • Local preferences. If you pick a light or dark theme, the choice is saved in your browser’s local storage (geocore-theme). It never leaves your device.
  • Docs search. Search runs in your browser against a file downloaded from this site; what you type is not sent anywhere.

Changes and questions

If GeoCore’s network behaviour changes, this page will be updated along with the code. The history of this page is public in the repository. Questions or concerns: open an issue on GitHub.
